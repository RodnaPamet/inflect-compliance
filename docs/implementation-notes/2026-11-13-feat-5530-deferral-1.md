**Commit:** see the branch `feat/feat-5530-deferral-1` (Step 2f, deploy 1 of 2).

## Design

"Deferral to a person" in `docs/claude-tool-runner-design.md` is the design, and
its owner decisions of 2026-11-13 are followed as recorded: only Inflect propose
tools a version names defer, decided in the existing proposal queue (1a); the
parked run reuses `AWAITING_APPROVAL`, told apart by its row (2a); the transcript
is cleared when the run resumes or settles, its hash kept (3a); an expiry settles
the run FAILED, a kill or suspension at the decision or the window's end (4a);
deferrals only (5a).

This deploy carries the table, the column and every READER, and no writer:

```
proposal queue decision ──▶ settleDeferralForProposal ──▶ deferral WAITING→DECIDED
 (approve / reject / bulk)        (usecase)                run AWAITING_APPROVAL→RUNNING (conditional)
                                                           checkpoint DONE, WORKFLOW_RUN_RESUMED, enqueue
expiry sweep  ─────────────▶ same hook (EXPIRED) ───────▶ run FAILED tool_runner_deferral_expired
retirement cascade ────────▶ settleRetiredAgentDeferralsInTx ▶ run FAILED tool_runner_deferral_agent_retired
abortWorkflowRun ──────────▶ settleOpenDeferralsInTx (same tx) ▶ deferral SETTLED NOT_RESUMED
worker → executeToolRunnerRun ─▶ openResume: seal → envelope → proposal row
        lockedParams({ resume }) + resumedToolsFor ─▶ first MODEL_CALL step + RESUMED/clear in one tx
executeFrom settlement ────▶ settleDeferralsAfterRun (any non-park outcome)
```

`RUNS_DEFERRALS` is false for every engine, so admission refuses a version naming
deferred tools (`PROFILE_DEFERRALS_NOT_RUNNABLE`), the worker treats such a pinned
version as unavailable, and the save and approval schemas, which are strict,
still refuse `deferredToolNames`. Deploy 2 adds the parking path, the save and
approval checks, the editor and the flag flip.

## Decisions

- **Two claims, deferral first.** The hook claims the deferral WAITING→DECIDED,
  then the run AWAITING_APPROVAL→RUNNING, both conditional. A run that is no
  longer parked (an operator aborted it) settles the deferral rather than
  resuming. Removing both conditions lets two decisions resume one run; the
  integration test proves it.
- **The hook reads the proposal's own status and reviewer.** Every caller passes
  only the id, so none can name a decision the queue did not record, and the
  sweep's heal resumes under the decider the queue recorded, not the sweep.
- **The heal.** The hook never throws to the decision path (the decision has
  committed). A deferral left WAITING behind a decided proposal is handed to the
  hook again by the nightly sweep.
- **RESUMED in the first step's transaction.** Marking it before the request
  would lose the decision on a crash; marking it after would let a retry resend
  a conversation whose continuation is in the ledger. `recordStep` gained an
  optional `alsoInTx` for it.
- **The clock.** The engine starts the resumed segment at
  `Date.now() - elapsedMsAtPark`; the hook also puts the same base in the job
  payload, so a retry of a segment that has already RESUMED keeps it.
- **`settleDeferralsAfterRun` in `executeFrom` and the worker's early refusals.**
  A kill or suspension found at the resume, a refused transcript or any other
  non-park outcome settles an open row and clears its transcript. A PAUSED run
  (SIGTERM) keeps a DECIDED row so the retry resumes from it.
- **`deferredToolNames` is not in the content hash**, as `toolNames` is not; it
  is frozen by the lifecycle function and held to `toolNames` by a CHECK.
- **The retirement effect is not in the cascade summary.** Settling the parked
  runs is the consequence of expiring their proposals, so it has its own audit
  row (`AGENT_RETIREMENT_PARKED_RUNS_SETTLED`) and the summary shape the
  response and its tests rely on is unchanged.
- **The view reads are a module of their own**, so a page that only reads does
  not load the hook's queue and audit imports.
