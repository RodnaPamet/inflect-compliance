## Design

Deploy 1 taught every reader what a parked run means. This deploy adds the one
writer and turns it on, last, in a commit of its own:

```
save / approval ── checkProfileDeferredTools ──▶ deferredToolNames (refused by name)
run: ledgeredCall(deferred tool)
   items ≠ 1 ─────────────────▶ FAILED TOOL_CALL, DEFERRED_CALL_ONE_ITEM (before the funnel)
   funnel → one PENDING proposal ─▶ TOOL_CALL {deferred, proposalId} → latch DEFER, abort signal
runModelLoop step 9: DEFER latched ─▶ keep the turn (request, reply, tool results); no compaction
settlement (DEFER is the lowest stop) ─▶ parkRun: transcript + PENDING checkpoint + RUNNING→AWAITING_APPROVAL
                                          (one transaction), WORKFLOW_RUN_DEFERRED
proposal queue decision ───▶ deploy 1's hook and resume branch
```

## Decisions

- **The latch follows the step.** The deferred call's `TOOL_CALL` is in the
  ledger, with `{ deferred: true, proposalId }`, before the run's signal is
  aborted, so the park always names a recorded call.
- **The proposal waited on is read from the queue by the call's step**
  (`runId`, `stepSeq`), not parsed out of the tool's result text. One PENDING
  row is a wait; a quarantined row, or none, is not.
- **The park's three writes are one transaction**, through `recordStep`'s
  `alsoInTx` (the checkpoint step stays in the step ledger's one write seam).
  An operator's ABORTED makes the conditional move fail and rolls the
  transcript back too: nothing waits on a stopped run.
- **The transcript pins `reply.model`**, the model the thinking blocks were
  produced on, and the tool definitions through `toolDefinitionOf`, the same
  stripping the summary request uses, so the resume sends the bytes the model
  saw.
- **The approval re-check also requires the stored list to be canonical**, so a
  row written by another build is refused rather than approved as it reads.
- **The flip is the last commit.** Before it, admission refuses every version
  naming deferred tools (`PROFILE_DEFERRALS_NOT_RUNNABLE`); reverting it restores
  that.
- **Found, not fixed here:** under the default `BALANCED` guard mode, every
  propose call through `runGuardedTool` is flagged on its own result, because
  the funnel's result JSON names `quarantined` and the injection scan's
  `inj.answer_steering.refusal_vocabulary` rule matches the word. The
  end-to-end test sets `AUDIT` and says why; the defect needs its own issue.
