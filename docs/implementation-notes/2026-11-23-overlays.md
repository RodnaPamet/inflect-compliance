# 2026-11-23 — Phone overlays: stacking sheets, the home indicator, a two-row bulk bar

**Commit:** see the pull request that closes #5810, #5811 and #5819.

## Design

Three shared primitives misbehaved on a phone, and each fix lives in the
primitive so every consumer gets it.

**The Popover's bottom sheet stacks its content** (`ui/popover.tsx`). The
drawer body was `flex items-center justify-center overflow-hidden` — a row. A
caller that passes several root nodes (the user menu passes a fragment:
identity header, theme row, language row, menu) had them laid side by side and
clipped at both edges. The body is now a column that stretches its children
and scrolls (`flex-col items-stretch overflow-y-auto`), inside a sheet capped at
`85dvh`. The user menu was the only consumer passing several roots; two
consumers that gave their single root a fixed width (`RiskScoreExplainer`'s
`w-80`, the filter operator menu's `w-32`) now take the sheet's width below
`sm` — the breakpoint at which the Popover presents as a sheet — and keep their
width above it. Menu rows (`Popover.Item`, the user menu's row recipe) get the
Button primitive's `pointer-coarse:min-h-11`.

**Every bottom sheet clears the home indicator and sizes by `dvh`.**

| Surface | Inset | Height |
|---|---|---|
| Popover sheet | body `pb-[calc(1rem+env(safe-area-inset-bottom))]`, plain `pb-4` while the keyboard is open | `max-h-[85vh]`, `85dvh` where supported |
| Modal sheet | `pb-[env(safe-area-inset-bottom)]` on the sheet, so the sticky footer sits above it | `max-h-[92vh]`, `92dvh` where supported |
| Modal dialog | — (centred) | `min(85vh,680px)`, `85dvh` where supported |
| Sheet, bottom | sits at `max(margin, inset)` via `--sheet-bottom` | `min(85dvh, viewport − margin − bottom)` via `--sheet-viewport` |

Every `dvh` class is behind `supports-[height:100dvh]:`, so a browser without
it keeps the old `vh` value rather than dropping the cap. The keyboard
avoidance (`useKeyboardInset` / `keyboardAvoidanceStyle`) is untouched: its
inline `paddingBottom` replaces the class-based inset while the keyboard is
open, which is the right answer — the indicator is under the keyboard then.

**The bulk-selection toolbar gets a phone layout** (`ui/table/selection-toolbar.tsx`,
`ui/bulk-action-bar.tsx`, `ui/table/data-table.tsx`). Below `md` the bar is two
rows: select-all, count and Clear on the first; the batch controls across the
whole second. `BulkActionBar` fills that row — picker stretched, Apply a 44 px
button that shows its word — and an action with a value input gives the picker
the full row and puts the input beside Apply on the next. On the card list the
bar DOCKS: it is rendered after the cards, `sticky bottom-0`, padded for the
inset, and not rendered as a box while nothing is selected. Desktop keeps the
one-row overlay; every phone class is the base and `md:` restores the old one.

| `src/components/ui/modal.tsx` | sheet inset padding; `dvh` caps on sheet and dialog |

| `src/components/ui/table/selection-toolbar.tsx` | two-row phone layout; `placement="dock"`; 44 px Clear and batch buttons on a phone |
| `src/components/ui/table/data-table.tsx` | the card branch mounts the toolbar docked, after the cards |
| `src/components/ui/bulk-action-bar.tsx` | full-width phone layout; Apply is a labelled `Button` on a phone, icon-only on desktop |
| `src/components/layout/user-menu.tsx` | 44 px coarse-pointer rows |

## Decisions

- **Sticky, not fixed, for the docked bar.** A sticky bar takes its own space at
  the end of the list, so it never covers the last card, and if some ancestor
  clips overflow it degrades to sitting after the list. A fixed bar would cover
  the last card unless every page reserved space for it, and under a
  transformed ancestor it is positioned against that ancestor instead of the
  screen.
- **`items-stretch`, not `items-center`, in the Popover sheet.** A centred
  column shrinks every child to its content, so separators collapse to nothing
  and menu rows stop at their text. Stretching is what a bottom sheet is; the
  cost is that a fixed-width child sits at the start, which is why the two
  fixed-width consumers were changed.
- **Apply stays one element with one id.** `#bulk-apply-btn` is what E2E
  drives, so the phone's labelled button and desktop's icon square are the same
  `Button`: the label is visible below `md` and `md:sr-only` above it, with the
  same `aria-label` either way.
- **`md:contents` on the picker and value wrappers.** The wrappers give the
  phone something to size; on desktop they are not boxes, so the row lays out
  as it did before they existed.
- **No change to `Modal.Footer`.** The inset is on the sheet rather than the
  footer, so the footer stays one recipe for the dialog and the sheet.
