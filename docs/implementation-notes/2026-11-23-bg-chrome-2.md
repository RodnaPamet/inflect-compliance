# 2026-11-23 — Bulgarian UI chrome, part 2: the rest of the server-built text

Closes the list #5858 left on #5826: the agentic bell body, the long tail of
audit-log codes, report metric definitions, agent control-test titles,
audit-procedure names and workflow names. Same rule as part 1: stored rows,
hashed content and evidence are never rewritten; translation happens where the
text is shown.

## Design

**Agentic bell bodies are read back from their own text.** A body is one fixed
sentence per notification type with a subject slot and a detail slot. Every
piece of English the emitter puts in a slot — "Every agent in this
workspace", `The tool "<name>"`, `Agent <id>`, the pin and owner-orphan detail
sentences, the breaker's signal codes, the staleness axes — is now built in
`src/lib/notifications/agentic-bodies.ts`, and the emitter writes its bodies
through `agenticBodyText`. The same module parses a stored body back into its
slots (`parseAgenticBody`) and renders it from `notificationBodies.*`
(`localizedNotificationBody`). Because the module reproduces the emitter's old
sentences byte for byte (pinned by `tests/unit/agentic-notification-bodies.test.ts`),
rows written before this change parse too and render translated. An agent's
name is shown as its owner wrote it; a body or detail the module did not write
is shown exactly as stored.

```
emit:    subject, detail ──agenticBodyText──▶ Notification.message (English, as before)
display: type + message ──parseAgenticBody──▶ {subject, detail}
                         ──localizedNotificationBody──▶ notificationBodies.body[WithDetail].<TYPE>
```

**Every audit code has a label.** `auditCodes.action.<CODE>` (530 codes) and
`auditCodes.entity.<key>` (294 entity types, keyed by `auditEntityKey`, so
`AccessReview` and `ACCESS_REVIEW` share one). The audit log's chip and entity
column take the catalog label first and keep part 1's composition and the
code-as-words as fallbacks; the dashboard feed uses the label for an action it
has no verb for ("Иво: Затваряне на преглед на достъпа") and for an entity it
has no noun for.

The population is read from the source, not hand-listed:
`tests/helpers/audit-code-population.ts` walks every object literal that
carries `action` beside `entityType`/`entity`, resolving literals,
conditionals, same-scope consts and `MAP.KEY` / `MAP[key]` over object
literals. What it cannot read (a parameter, an imported constant, a computed
prefix) is reported by location, and the guard holds those sites against a
map that names the codes each writes — so a new `logEvent` with a new code, or
a new site the scan cannot read, fails CI until it is labelled. The Prisma
audit extension writes every model's name, so every model in the schema needs
an entity label too.

**Metric definitions** render from `agentMetrics.<group>.<name>.{label,
population, includes, excludes}` (`src/lib/agentic/report-definition-text.ts`).
The governance pack's payload and export keep the registry's English. The
guard holds the English catalog equal to `METRIC_DEFINITIONS` word for word,
so editing a definition without its translation fails CI rather than showing a
stale Bulgarian sentence.

**Check titles, procedure names and plan names.** The five check titles moved
to the client-safe `src/lib/agentic/agentic-check-titles.ts`, which
`AGENTIC_CHECKS` now reads. The assurance panel, its setup preview and its
refusals (the setup returns a `message` key with the facts its English
`detail` is written from) render from `agentChecks.*`. Procedure names reuse
the existing `audits.workpaperReviews.procedureName.*` on the audit-pilot page
and the reliance snapshot. The test-plan names the assurance setup and the
audit pilot write ("Agent assurance: …", "Audit procedure: … (<id>)") render
translated on the test pages while they are still the stock name; a renamed
plan is shown as written.

**Workflow names** render from `agentWorkflows.<key>.{name,description}` on the
runs list and detail, the agent's runs tab, the start forms, the peers pages,
the decisions page and the rule builder.

## Decisions

- **No column, no migration for the bell body.** The issue asks that existing
  rows render translated; a new structured column would only help new rows.
  The stored text already carries the structure, because the sentence is fixed
  per type — so the type is the message code and the slots are the params.
- **Display only, everywhere.** Audit rows, evidence titles and content, stored
  plan names, workpapers, the governance pack's payload and the reliance
  snapshot's stored definitions keep their English. The reliance snapshot's
  definitions are a frozen artefact and are shown as frozen; only its procedure
  names (stable per id) are translated.
- **English catalog values are the registry's own text** for metrics, workflows,
  checks and procedures, and the guard compares them, so the two cannot drift.
  The English audit labels are the code as words (what the log showed before),
  with product names spelled properly.
- **What a Bulgarian label may keep in Latin** is a short named set: product,
  vendor and standard names, acronyms, and "service principal" (owner decision
  of 2026-10-30). Metric definitions keep table, column and enum names, which
  an assessor cites as written.
- **Still English by design:** evidence rows the agentic control tests write
  (title and body are evidence), the `Details` column of the audit log (the
  writer's own sentence), and workflow step names on a run's timeline (they
  are the definition's step identifiers, not part of #5826's list).
