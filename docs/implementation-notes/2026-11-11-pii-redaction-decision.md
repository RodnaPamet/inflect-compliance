**Commit:** see the `wf/presidio-phase0` branch — Phase 0 of

## Design

Phase 0 decides what the detector is for and measures it before anything uses
it. Nothing on any request path changes: no service, no egress wiring, no
setting (Phases 1 and 2).

```
tests/fixtures/pii/generate.ts ──▶ corpus.json + corpus.sha256      (TS, seeded, regenerated by a test)
            │
            ▼
guards/presidio/inflect_pii/  (Python, image source only — G5)
   egn.py           ЕГН: date AND weighted checksum
   recognizers.py   BgEgn, BgPhone, BulgarianName, OfflineEmail
   config.py        registry = exactly the five types; config_hash()
guards/presidio/evaluate.py ──▶ evals/pii/records/<hash16>.json     (raw spans, no rates)
            │
            ▼
src/lib/ai/pii/evaluation-record.ts  — corpus + record schemas; P/R RECOMPUTED per type, per locale
```

The corpus and the record follow the house shape (G11) of
`flue/skills/evaluation-record.ts`: a hash-named set, a record that is the set
plus one configuration's raw answers, rates recomputed every time, a record
that states its own rate refused, four case kinds required. For a detector the
kinds read: **task** (find the PII), **refusal** (decline a near-miss: ten
digits failing the ЕГН checksum, ten digits with a valid checksum on month 13,
control codes, organisations, addresses), **injection** (instructions to the
redactor around real PII change nothing), **missing-input** (blank fields, the
empty string, text already carrying `<PERSON_1>` placeholders).

## D-L1-1 — recorded (owner decision, initialled 2026-11-11)

| Question | Decision |
| --- | --- |
| Egress paths | **External model routes only** (`inflect-external`). A2A outbound and anything else is not in scope until a later decision names it; the SIEM stream stays structured-only. |
| `LOCAL_ONLY` tenants' local route | **Off** — not redacted; nothing leaves the perimeter there (`LOCAL_ROUTE_REDACTED = false` in `src/lib/ai/pii/scope.ts`). |
| Entity types | **PERSON, EMAIL, PHONE, IBAN, Bulgarian ЕГН** — in Presidio's spelling `PERSON`, `EMAIL_ADDRESS`, `PHONE_NUMBER`, `IBAN_CODE`, and `BG_EGN` for the custom recogniser. LOCATION and ORG are **not** in scope (the roadmap's draft had LOCATION and "ORG flag-only"); the analyzer does not load a recogniser for either. |
| Locales | **EN + BG**, scored separately so a BG gap cannot hide behind EN. |
| Action per type | Not stated by the decision. Phase 0 records the default the roadmap's Phase 2.3 already presumes: **replace with a numbered typed placeholder** (`<PERSON_1>`), never reversed on the way back. Phase 1's `policy.ts` encodes it; a different action for one type is a reviewed diff there. |

## The first record

`evals/pii/records/e6ff3ad0d4d33dba.json` — presidio-analyzer 2.2.366,
`en_core_web_sm@3.8.0` (EN), `xx_ent_wiki_sm@3.8.0` (BG), configuration
`sha256:e6ff3ad0…`, corpus `sha256:71478f35…` (85 cases). Recomputed by
`scorePiiRecord`:

| Type | EN recall | EN precision | BG recall | BG precision |
| --- | --- | --- | --- | --- |
| PERSON | 22/22 | 22/31 (0.71) | 24/24 | 25/26 (0.96) |
| EMAIL_ADDRESS | 9/9 | 9/9 | 8/8 | 8/8 |
| PHONE_NUMBER | 8/8 | 8/8 | 10/10 | 10/10 |
| IBAN_CODE | 6/6 | 6/6 | 5/5 | 5/5 |
| BG_EGN | 7/7 | 7/7 | 7/7 | 7/7 |

Cases passed per kind: task 43/46, refusal 18/23, injection 10/10,
missing-input 5/6. Every miss is the NER model calling a non-person a PERSON
("Batch 9813040421", "Release 3.338.0", "Sampleford", "София", the field label
"Email"). No in-scope PII was missed.

**Read these as development-set figures, not as a measure.** The recognisers
were written and corrected against this very corpus (the Latin-script
Bulgarian-name pattern exists because `en_core_web_sm` missed "Radka
Stoyanova"; the date guard because "02.11.2026" is a valid Sofia number). The
identity-match record learned in #3462 what a figure measured on the set it was
tuned on is worth: 1.0 there and 0.571 off it. Before a record becomes Phase 1's
mount condition it needs a HELD-OUT corpus — different templates and different
name pools, generated by a different seed — scored beside this one.

## Decisions

- **The corpus is generated by TypeScript, in `tests/`, and a Jest test
  regenerates it.** A committed corpus that differs from the generator's output
  by one byte fails CI, so nothing can be pasted into it by hand — which is how
  a real person would arrive in it. Python never writes it, so G5 holds.
- **Offsets are UTF-16 code units and the corpus stays in the BMP.** JS and
  Python agree on offsets exactly then; the schema refuses a surrogate, so the
  same spans are valid on both sides of the Phase 1 HTTP seam.
- **Recall is "nothing leaks", precision is bounded over-reach.** A gold span
  is recalled only if every non-whitespace character is covered by a prediction
  of its type; a prediction is correct if it overlaps a gold span of its type
  and at most `OVERREACH_CHARS` (8) of its characters lie outside that span,
  before it and after it together. (The first cut bounded the prediction's
  LENGTH, which a span shifted almost wholly beside the name passes; the
  committed record's figures were unchanged by the correction, and a test now
  pins them.) Out-of-scope types are ignored,
  not penalised. No predictions is `null` precision, never 1.
- **The registry is built from nothing.** Presidio's predefined recognisers
  (credit cards, US SSNs, …) are not loaded; a type outside D-L1-1 cannot be the
  reason a payload changed.
- **`OfflineEmailRecognizer`.** Presidio's e-mail validation asks `tldextract`,
  which (a) refuses every private or reserved TLD — `corp.local` addresses
  still identify people — and (b) fetches the public suffix list from
  publicsuffix.org on first use, an egress the in-deployment service must not
  make. Measured: with the stock recogniser, 0 of 17 fixture e-mails were found.
- **`BgPhoneRecognizer` regions BG + GB.** Under Presidio's default regions an
  ЕГН is also a valid North American phone number, so a correctly found ЕГН
  came back a second time as `PHONE_NUMBER`. A written date is dropped because
  `02.11.2026` is a valid Sofia number.
- **Bulgarian names by morphology, in both scripts.** No spaCy pipeline is
  trained on Bulgarian; `xx_ent_wiki_sm` (WikiNER, includes Russian) is the BG
  NER, and the pattern — given name, optional patronymic, family name, the
  last two carrying -ов/-ев/-ова/-ева/-ски/-ска/-цки/-цка — is the
  deterministic half. Case-sensitive: under Presidio's default IGNORECASE every
  lower-case "-ова" word pair would be a name.
- **Small models first** (D-L4-3's rule applied here): `en_core_web_sm` rather
  than Presidio's default `en_core_web_lg`. A larger model is adopted only by a
  record showing it earns its memory on the VM.
- **`config_hash()` covers `requirements.txt` and every module of
  `inflect_pii`, by path and bytes**, and the Jest suite recomputes it the same
  way: a recogniser edit without a new record fails CI today, before Phase 1's
  mount gate exists.
- **Not done here, deliberately:** the HTTP service, Compose entry, capacity
  line, `PiiDetector` seam, settings and egress wiring (Phases 1–2). The image
  has no entrypoint and appears in no Compose file. No CI job builds it yet; the
  Python tests were run locally from a venv built from the committed pins.
