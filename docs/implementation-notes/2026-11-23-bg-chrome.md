# 2026-11-23 — Bulgarian UI chrome: dates, helper literals, server-built text, raw enums

Phase 2 of `docs/mobile-roadmap.md` (#5824–#5828). The 2026-11-22 mobile audit
found English on 116 Bulgarian pages that a translated `bg.json` could not fix,
because the English never went through the catalog.

## Design

**Dates follow the reader's language without touching the call sites.**
`packages/ui/src/lib/format-date.ts` keeps its UTC pinning and its exported
helper names, and every helper now reads an ACTIVE locale. The root
`<Providers>` calls `useBindDateLocale()` once per render, which hands
next-intl's `useLocale()` to `bindDateLocale()` before anything below renders.

```
<Providers>  useLocale() ──bindDateLocale──▶  browser: module value (one tab, one locale)
                                              server:  AsyncLocalStorage.enterWith (one request)
   └─ any component ── formatDate(x) ──▶ FORMATTERS[activeDateLocale()]
server component ── await getDateFormatters() ──▶ dateFormattersFor(await getLocale())
jobs / routes / PDFs ── formatDate(x) ──▶ no binding ⇒ English, as before
```

The server half is the part that matters: a module variable would let a
Bulgarian request and an English request that render concurrently format each
other's dates, and a server string that differs from the client's is a
hydration mismatch. The store is entered during the request's own render, and a
render resumed after suspense continues in that request's async context.
`globalThis.AsyncLocalStorage` (which Next.js installs) is used rather than
`node:async_hooks`, because this module is bundled for the browser too.

Server components do not sit under `<Providers>` in the RSC pass, so the six
that format dates take `getDateFormatters()` (`src/lib/i18n/date-format-server.ts`).

Bulgarian is TABLE-DRIVEN, not `Intl.DateTimeFormat('bg')`. Intl's `bg` output
depends on the ICU/CLDR build: Node prints `{month: 'short'}` as `04`, and a
browser on another CLDR version can add or drop a `г.`, which would be a
hydration mismatch. A table writes the same bytes everywhere. English keeps the
exact `en-GB` output it had. Relative time passes date-fns' `bg` locale; the
date pickers default to the active date-fns locale instead of `enUS`.

**Helper literals become catalog keys.** `describeRoiGap` returns a key under
`controls.roi.gap`; `TreeExpandCollapseToggle` defaults to `common.ui.expandAll`
/ `collapseAll`; the celebration registry stores catalog keys and
`milestoneCopy()` resolves them, `scopedMilestone()` taking the translated copy.

**Defaults the product wrote are translated at display time; names the tenant
wrote are not.** `localizeRiskMatrixConfig` swaps a level label only while it
equals the default at its position, a band name only while it equals a default
band name, an axis label only while it equals the default. It is applied by
`useRiskMatrixConfig` and on the risks list; the stored row, the admin editor
and the API are untouched. Org widget titles work the same way: the create path
stores the stock English title, so `localizedWidgetTitle` reads a stored title
equal to its stock title as "not renamed" and shows `org.widgets.*` — rows
written before this change render translated too. Agentic bell titles are fixed
per type, so `localizedNotificationTitle` does the same against
`AGENTIC_NOTIFICATION_TITLES`, which the emitter now also reads.

**Server-built sentences are composed on the client.** The BIA detail page
renders `audits.biaDetail.recoveryRationale` from the BIA's own criticality,
MTPD, RTO and rank; the service keeps its English `rationale` for the API. The
dashboard activity feed and the audit log's action chips share
`activityEventToken` (whole-action events such as `AUTH_LOGIN_SUCCESS`, which
read as "signed in" with no entity noun), the generic bare-verb aliases
(`UPDATE` → `UPDATED`) and `activitySubject` (the entity an action names). The
chip is composed by the catalog: English "Risk created", Bulgarian "Създаване на
риск". The org threat-level widget's unset default ("No active threat
assessment", built by the usecase) renders from `org.widgets.noThreatAssessment`
when `isDefault` is set.

A date formatted at module LOAD is frozen in whichever language loaded the
module first — the calendar's weekday headers were built that way — so headers
are built at render and the guard refuses a module-level call to a date helper.

**Raw enums** go through the label maps that already existed (member status,
ISO 27002 theme categories on framework templates, AI-governance criticality,
agent-run status on the process canvas) or new ones (process-map status,
agent-surface severity).

## Decisions

- **Ambient binding over a hook per call site.** About 360 calls in 148 client
  files format dates; a per-component hook would have touched all of them and
  every future one. The cost is one rule: a server component formats through
  `getDateFormatters()`, which the guard enforces over `src/app`.
- **What stays English, and why.** The agentic notification BODY (the subject and
  detail are interpolated into prose at emit time and not stored apart); the
  long tail of audit actions with no known verb (about 470 codes; the feed shows
  a generic Bulgarian phrase, the chip the code as words); report metric
  definitions (65 metrics with label, population, includes and excludes);
  agent control-test text; audit-procedure names; workflow names on the agent
  runs page, which another change owns. Stored data is never rewritten.
- **The back-link labels (I1)** live in `canonical-parents.ts`, which another
  open change owns, so the guard does not cover that class.
- **No Phase 0 baseline to lower.** The Phase 0 whole-product ratchet has not
  landed; the guard here starts at zero and carries no allowlist.
